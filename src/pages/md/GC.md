### GC 垃圾回收机制
#### 1. 什么是垃圾回收
垃圾回收（Garbage Collection，简称GC）是编程语言中自动内存管理的机制，用于回收不再使用的内存空间，防止内存泄漏。

#### 2. 垃圾回收的原理
垃圾回收的原理是追踪所有对象的使用情况，当某个对象不再被引用时，该对象所占用的内存空间就会被回收。

#### 3. 垃圾回收的算法
垃圾回收的算法有很多种，常见的有标记-清除算法、复制算法、标记-整理算法等。
- 标记-清除算法：从根对象出发标记所有可达（存活）对象，未被标记的对象才会在清除阶段被回收
- 复制算法：把存活对象复制到另一块内存空间，然后整块清掉旧空间
- 标记-整理算法：标记-清除算法的改进版，在清除阶段之前，先对存活对象进行整理，使得内存空间更加紧凑。先标记存活对象，再把它们向一端移动，最后清掉边界外内存

#### 4. 垃圾回收的时机
垃圾回收的时机通常由垃圾回收器（Garbage Collector，简称GC）来决定，常见的有手动触发和自动触发两种方式。
- 手动触发：通过调用垃圾回收器的API来手动触发垃圾回收
- 自动触发：垃圾回收器会根据内存使用情况自动触发垃圾回收，常见的触发条件有内存不足、内存使用达到一定阈值等

#### 5. 垃圾回收的性能优化
垃圾回收的性能优化主要包括减少垃圾回收的频率、减少垃圾回收的耗时、减少内存碎片等。

#### 6. 常见内存泄漏
常见的内存泄漏包括以下几种：
- 全局变量：全局变量在程序运行期间不会被回收，如果全局变量引用了大量的对象，会导致内存泄漏
- 闭包滥用：闭包会引用外部函数的变量，如果闭包没有被释放，会导致内存泄漏
  ```js
    function createClosure() {
      let largeArray = new Array(1000000);
      return function() {
        // 使用 largeArray
        console.log(largeArray)
      };
    }
    let closure = createClosure();
    // closure 不会被回收，因为 createClosure 返回的闭包引用了 largeArray
  ```
- 事件监听器：事件监听器在组件销毁后没有被移除，会导致内存泄漏
  ```js
    window.addEventListener('resize', handler);

    // 未执行移除事件监听器的操作
    // window.removeEventListener('resize', handler);
  ```
- DOM 元素：DOM 元素在组件销毁后没有被移除，会导致内存泄漏
  ```js
    let element = document.getElementById('my-element');

    // 未执行移除 DOM 元素的操作
    // document.body.removeChild(element);
  ```
- 定时器：定时器在组件销毁后没有被清除，会导致内存泄漏
  ```js
    let timer = setInterval(() => {
      // 定时器回调函数
    }, 1000);

    // 未执行清除定时器的操作
    // clearInterval(timer);
  ```

#### 7. 常见内存泄漏排查方法
常见的内存泄漏排查方法包括：
- 使用浏览器的开发者工具：大多数现代浏览器都提供了开发者工具，可以用来查看内存使用情况，找出内存泄漏的源头
- 使用内存分析工具：内存分析工具可以帮助我们更深入地了解内存使用情况，找出内存泄漏的具体原因
- 使用代码审查：代码审查可以帮助我们找出潜在的内存泄漏问题，例如全局变量、闭包滥用、事件监听器、DOM 元素、定时器等
